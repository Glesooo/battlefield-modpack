# tools

## make_manifest.py

Создаёт `manifest.json`: полный список файлов сборки для лаунчера и сервера. Читает игру в Prism
(`instances\M.A.C.E\minecraft`), ничего в ней не меняет и ничего не публикует.

```
python tools\make_manifest.py
```

Рядом с репозиторием появляется папка `PackStage` с файлом `<хеш>-base.zip`: это архив с конфигами и
стартовыми настройками.

Адреса игрового сервера нет ни в списке сборки, ни в архиве: список серверов игры (`servers.dat`) в сборку
не входит. Адрес знает только мод меню, которому он нужен для подключения.

Повторный запуск без изменений в игре даёт тот же `revision`.

### Формат manifest.json

| Поле | Значение |
|---|---|
| `revision` | отпечаток содержимого сборки; меняется при любом изменении |
| `minecraft`, `forge`, `java` | версии, которые ставит лаунчер |
| `sources` | базовые адреса для скачивания; лаунчер пробует их по очереди. Ссылка на файл = адрес + `asset` |
| `folders` | правило для папки игрока, см. ниже |
| `files` | большие файлы по одному: `path`, `size`, `sha256`, `asset` |
| `bundle` | один архив с мелкими файлами: `asset`, `size`, `sha256` и список `files` с `path`, `sha256`, `mode` |

Имя `asset` начинается с первых 16 знаков SHA-256, поэтому новая версия файла никогда не затирает старую,
а в имени остаются только латиница, цифры, точка, дефис и подчёркивание.

### Правила папок

| Значение | Поведение лаунчера |
|---|---|
| `strict` | в папке лежит ровно то, что в списке; лишнее переносится в `removed` |
| `strict_zip` | то же, но только для архивов в корне папки. Подпапки `tacz` создаёт сам мод TaCZ из своих jar-файлов |
| `additive` | файлы из списка докачиваются, чужие остаются (шейдеры) |

### Режимы файлов в архиве

| `mode` | Поведение |
|---|---|
| `managed` | перезаписывается при каждом запуске, если отличается |
| `first_install` | ставится, только если файла ещё нет; дальше принадлежит игроку |

Конфиг, который мод сам переписывает при каждом старте игры, должен быть `first_install`, иначе лаунчер
будет восстанавливать его при каждом запуске. Так было с `packetfixer.properties`: мод каждый раз
вписывает в него текущую дату. Проверка после запуска игры: повторная синхронизация должна сообщить
«конфигов 0».

### Что не попадает в сборку

- `config\battlefieldcore-admin.toml`: в нём был пароль `/adm`. С версии MACE Core 1.7.1 команды `/adm` нет
  и файл больше не создаётся, но в старой папке игры он мог остаться. Скрипт проверяет перед записью, что
  файл не попал в архив, и падает, если попал.
- Настройки графики: `embeddium-options.json`, `embeddium-fingerprint.json`, `oculus.properties`, `fml.toml`.
  Игрок получает стандартные.
- `config\e4mc`: мод для игры через чужой ПК, игрокам не нужен.

### Стартовый options.txt

Собирается из `options.txt` Gleso: клавиши, чувствительность и переключатели мыши, язык и список
включённых ресурспаков. Настройки графики и звука в него не попадают, игра подставит стандартные.
Дополнительно отключены обучающие подсказки и предупреждение о сетевой игре.

## upload_pack.py

Выкладывает сборку в релиз `pack` репозитория `Glesooo/battlefield-modpack`. Работает через `gh`
(GitHub CLI), вход в который уже выполнен.

```
python tools\upload_pack.py                    показать, что будет загружено; ничего не меняет
python tools\upload_pack.py --publish          загрузить недостающие файлы и новый manifest.json
python tools\upload_pack.py --publish --prune  то же и удалить из релиза файлы, которых нет в сборке
python tools\upload_pack.py --stage ПАПКА      сложить сборку в папку на диске, без GitHub
```

Порядок работы:

1. Сверяет папку игры с `manifest.json`. Если после `make_manifest.py` в игре что-то изменилось, добавилось
   или пропало, останавливается и просит запустить его заново.
2. Спрашивает у GitHub список файлов релиза и загружает только те, которых там нет или у которых другой
   размер. Имя файла содержит начало его SHA-256, поэтому совпавшее имя означает то же содержимое.
3. Проверяет, что все файлы сборки появились в релизе, и только после этого загружает `manifest.json`.
   Игроки не получат список, который ссылается на ещё не загруженный файл.
4. С `--prune` удаляет из релиза файлы прошлых версий.

Релиз создаётся при первой публикации. Первая загрузка: около 717 МБ.

`--stage` складывает те же файлы под теми же именами в папку вместе с `manifest.json`. Такую папку лаунчер
принимает как источник (`--source ПАПКА`); на ней работают проверки из `launcher\tests`. Файлы
связываются жёсткими ссылками с файлами игры и места не занимают; менять их нельзя.

После публикации сборку проверяет сам лаунчер: установка в пустую папку скачает каждый файл и сверит
его сумму.

```
MACE.exe --headless --sync --dir ПУСТАЯ_ПАПКА
```

### Конфиги HudElements

С версии мода 1.6.1 их два:

- `battlefieldhud-rules.toml`: выносливость, разбег спринта, покачивание камеры и оружия. Режим `managed`,
  одинаков у всех.
- `battlefieldhud-client.toml`: положение, размер и видимость панели и хотбара. В сборку не входит: мод
  создаёт его сам со стандартным раскладом, дальше игрок двигает элементы как хочет. Расклад Gleso
  подобран под экран 1600×900 с масштабом интерфейса 2 и на других экранах уезжает от углов.

Граница возможностей: `managed` возвращает значения при каждом запуске лаунчера, но не мешает править
файл, пока игра открыта. Настоящий запрет даст только сервер (этап 4).
