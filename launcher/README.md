# Лаунчер M.A.C.E

Исходный код лаунчера сборки M.A.C.E. Открыт, чтобы каждый мог проверить, что делает программа.

Статус (7 октября 2026): работают синхронизация сборки, установка игры и запуск. Проверено на деле:
установка сборки в пустую папку через окно, главное меню M.A.C.E, вход на сервер под офлайн-ником.
Сборка выложена в релиз `pack` этого репозитория. Окно сделано по фону из референса, полный дизайн
впереди. Пароль на ник сделан в лаунчере и в моде MACE Core и проверен входом в игру на местном сервере
(`tests\auth_game_check.py`).

## Что делает лаунчер

1. Скачивает список сборки `manifest.json`, сверяет с ним папку игры и докачивает изменившиеся файлы.
2. Убирает из `mods`, `resourcepacks` и из архивов ганпаков в `tacz` всё, чего нет в сборке. Чужие файлы
   переносятся в папку `removed`, файлы прошлых версий сборки удаляются.
3. Раскладывает конфиги: правила игры перезаписываются, личные настройки ставятся один раз.
4. Ставит Minecraft 1.20.1, Java 17 и Forge 47.4.10 с официальных серверов Mojang и Forge.
5. Запускает игру под ником игрока и передаёт ей ключ ника, вычисленный из пароля.

Адреса игрового сервера лаунчер не знает и к серверу не обращается: подключением занимается меню игры.

## Что он не делает

- Не спрашивает пароль от аккаунта Microsoft. Пароль в окне придумывает сам игрок, он нужен только
  для ника в M.A.C.E.
- Не сохраняет и никуда не отправляет пароль.
- Не требует прав администратора и ставится в свою папку.
- Не смотрит никуда, кроме папки сборки.
- Не открывает страницы в браузере.
- Не остаётся в автозапуске и не работает в фоне: после запуска игры закрывается. Удаляется удалением папки.

## Папки

По умолчанию `%APPDATA%\MACE`:

| Путь | Что там |
|---|---|
| `launcher.json` | ник и настройки запуска |
| `secret.bin` | ключ ника, зашифрованный Windows под учётную запись пользователя |
| `launcher.log` | журнал последнего запуска, предыдущий в `launcher.old.log` |
| `files.json` | размеры, даты и суммы файлов сборки для быстрой проверки при запуске |
| `game\` | Minecraft, Forge, библиотеки, ресурсы, Java |
| `instance\` | папка игры: моды, конфиги, ганпаки, ресурспаки, шейдеры, миры |
| `removed\` | убранные чужие файлы, по папке на каждый запуск |
| `cache\` | архив конфигов текущей версии сборки |

## Как устроено

| Файл | Назначение |
|---|---|
| `Core\PackManifest.cs` | разбор списка сборки и проверка каждого его поля |
| `Core\PackSync.cs` | загрузка списка, сверка, правила папок, архив конфигов |
| `Core\Downloader.cs` | скачивание: несколько адресов по очереди, докачка, проверка SHA-256 |
| `Core\FileIndex.cs` | кэш сумм: файл не перечитывается, если не менялись размер и дата |
| `Core\FileOps.cs` | замена и удаление файлов с повтором, если файл временно занят |
| `Core\Game.cs` | установка Minecraft и Forge через CmlLib (Forge без рекламной страницы), сборка команды и запуск |
| `Core\OfflineProfile.cs` | офлайн-идентификатор игрока, тот же, что вычисляет сервер |
| `Core\NickKey.cs` | ключ ника: вычисление из пароля и хранение |
| `Core\LauncherSettings.cs` | настройки запуска: память, экран, параметры Java |
| `Cli.cs` | режим без окна для проверок |
| `MainWindow.xaml` | окно |

### Список сборки

Список берётся только с адресов, записанных в самом лаунчере. Адреса из списка используются только для
файлов, и каждый файл сверяется по SHA-256 из списка.

До использования список проверяется целиком и отвергается, если в нём есть хоть одно нарушение:

- путь файла выходит за папку игры, начинается с диска или содержит `..`;
- имя файла для скачивания или контрольная сумма не подходят под строгий шаблон;
- адрес источника не `https`;
- у папки или конфига неизвестное правило;
- формат списка новее, чем понимает лаунчер.

### Скачивание

- Файл качается во временный `имя.mace-part` рядом с целью и занимает её место только после проверки суммы.
- Оборванная загрузка продолжается с места обрыва, в том числе с другого адреса. Если сервер не умеет
  отдавать файл с середины, файл качается заново.
- Адреса пробуются по очереди, по две попытки на адрес. Ответ «нет файла» (404, 403) на том же адресе не
  повторяется. Адрес, с которым не удалось соединиться или связь оборвалась, для следующих файлов уходит
  в конец очереди.
- Соединение, по которому 30 секунд не приходят данные, сбрасывается.
- Одновременно качаются четыре файла. Первая же неустранимая ошибка останавливает остальные загрузки.
- Сообщение об ошибке называет файл и последний адрес.

### Файлы на диске

- Если файл занят другой программой, операция повторяется пять раз с паузой 0,3 секунды: так антивирус
  успевает отпустить только что скачанный файл. Если файл занят и дальше, лаунчер спрашивает у Windows,
  какая программа его держит (`Core\FileHolders.cs`, диспетчер перезапуска Windows), и называет её:
  «Файл … занят программой javaw. Закройте её и попробуйте снова». Если узнать не удалось, сообщение
  советует закрыть игру. Скачанное при этом сохраняется до следующего запуска.
- Файл «только для чтения» перезаписывается как обычный.

### Установка Forge

Forge ставится частями библиотеки CmlLib.Core.Installer.Forge, а не её готовой командой `ForgeInstaller.Install`:
та после установки открывает в браузере рекламную страницу Forge (`adfoc.us`), и выключателя у неё нет.
`Game.InstallForgeAsync` делает те же шаги сам и браузер не трогает:

1. Если версия `1.20.1-forge-47.4.10` уже установлена, больше ничего не делается и к сайту Forge лаунчер
   не обращается.
2. Иначе с `files.minecraftforge.net` берётся список версий, из него адрес установщика на официальном
   хранилище Forge.
3. Установщик скачивается и выполняется той же Java, что ставится для игры.

Реклама на странице загрузки кормит разработчиков Forge. Поддержать их напрямую можно на
[Patreon Forge](https://www.patreon.com/LexManos).

### Пароль на ник

Офлайн-ник ничем не защищён: чужой ник может вписать кто угодно. Пароль закрепляет ник за игроком.

- Из ника и пароля лаунчер вычисляет пару ключей. Пароль проходит PBKDF2-HMAC-SHA256 с 600 000 проходов
  и солью `M.A.C.E nick key v1:` + ник строчными буквами; результат становится закрытым ключом на кривой
  P-256. Одни и те же ник и пароль дают один и тот же ключ на любом ПК.
- Пароль не сохраняется и никуда не отправляется. Закрытый ключ не покидает ПК.
- Ключ лежит в `secret.bin`, зашифрованный средствами Windows (DPAPI) под учётную запись пользователя.
  У другого пользователя или на другом ПК файл не читается, и пароль нужно ввести заново.
- Игре ключ передаётся переменными окружения `MACE_KEY` и `MACE_PUBLIC`. В командную строку он не
  попадает: её видят другие программы, и она пишется в журналы. В `launcher.log` пишется только
  открытая половина ключа.
- При входе сервер присылает случайное число. Мод MACE Core подписывает его ключом, сервер сверяет
  подпись с открытым ключом, который запомнил при первом входе под этим ником. На сервере лежит только
  открытый ключ: войти по нему нельзя, а подбор пароля по нему стоит 600 000 проходов на каждую попытку.
- Пароль не короче 6 символов. Галочка «Показать» открывает набранное, чтобы не закрепить ник за опечаткой.
- После первого нажатия «ИГРАТЬ» вместо поля стоит «Пароль сохранён на этом ПК». «Ввести заново»
  возвращает поле: так исправляют неверно набранный пароль. Сменить пароль ника сам игрок не может:
  запись ника на сервере сбрасывает администратор, и следующий вход задаёт новый пароль.
- Ник в любом регистре даёт один и тот же ключ, но сервер требует писать ник так же, как при первом входе.

### Настройки

Ссылка «Настройки» в окне открывает панель с параметрами запуска игры. Они хранятся в `launcher.json`.

| Настройка | Поле в `launcher.json` | Что делает |
|---|---|---|
| Память для игры | `MaxMemoryMb` | предел памяти Java, шаг 250 МБ. Нижняя граница 3000 МБ: меньше сборке не хватает. Верхняя: память ПК минус 1000 МБ, но не больше 16000. По умолчанию 4000 |
| Запускать игру на весь экран | `FullScreen` | игра открывается в полноэкранном режиме. В самой игре режим переключает F11 |
| Размер окна | `WindowWidth`, `WindowHeight` | размер окна игры, если полный экран выключен. Пусто: стандартные 854×480 |
| Дополнительные параметры Java | `JavaArguments` | параметры через пробел, каждый начинается с «-». Добавляются перед параметрами памяти, поэтому `-Xmx` отсюда не действует |

Там же ссылки на папку шейдеров, журналы игры и журнал лаунчера. «По умолчанию» возвращает значения в
полях, но сохраняет их только кнопка «СОХРАНИТЬ».

### Окно

- Одновременно работает одна копия лаунчера.
- Закрытие окна во время работы останавливает её, затем лаунчер закрывается.
- После старта игры лаунчер ждёт 10 секунд. Если игра за это время закрылась с ошибкой, он остаётся
  и показывает её код; иначе закрывается.

Если Forge не установился, в журнал пишутся последние 200 строк вывода его установщика.

## Ключи запуска

```
MACE.exe [--dir ПАПКА] [--source АДРЕС_ИЛИ_ПАПКА ...]
MACE.exe --headless [--dir ПАПКА] [--source АДРЕС_ИЛИ_ПАПКА ...] [--sync] [--verify]
         [--install] [--print-launch] [--launch] [--join АДРЕС] [--nick НИК] [--password ПАРОЛЬ]
MACE.exe --headless --selftest
MACE.exe --screenshot окно.png
```

| Ключ | Что делает |
|---|---|
| `--dir` | папка лаунчера вместо `%APPDATA%\MACE` |
| `--source` | откуда брать сборку вместо GitHub: адрес или папка на диске; можно указать несколько |
| `--headless` | работа без окна |
| `--sync` | сверяет и докачивает сборку |
| `--verify` | при сверке пересчитывает суммы всех файлов, не доверяя кэшу |
| `--install` | ставит Minecraft и Forge |
| `--print-launch` | ставит игру и пишет в журнал команду запуска, не запуская игру |
| `--launch` | ставит и запускает игру |
| `--join АДРЕС` | вместе с `--launch` или `--print-launch`: игра после загрузки сама подключается к указанному серверу, минуя главное меню и его проверку сервера. Нужен для проверок |
| `--password ПАРОЛЬ` | вместе с `--launch` или `--print-launch`: ключ ника вычисляется из этого пароля и в `secret.bin` не записывается. Без ключа берётся сохранённый ключ, если он от этого ника. Только для проверок: командную строку видят другие программы |
| `--selftest` | проверяет офлайн-идентификатор, правила ника, защиту от путей вне папки игры, отбраковку испорченных списков сборки, ключ ника (эталонный ответ, зависимость от ника и пароля, шифрованное хранение) |
| `--screenshot` | рисует окно в PNG, не показывая его на экране |

Без окна код возврата 0 при успехе, 1 при ошибке. Подробности в `launcher.log` в выбранной папке.

Список сборки нужен при любом запуске без окна: из него берутся версии игры. Без
`--source` он берётся из релиза `pack` на GitHub.

Игра запускается с типом пользователя `legacy`: с типом `msa` она при каждом старте пытается получить
ключ профиля Microsoft и пишет в журнал ошибку. После старта в `launcher.log` появляется строка
`игра запущена, PID N`.

## Сборка из исходников

Нужен .NET SDK 8.

```
cd launcher\MaceLauncher
dotnet build
dotnet publish -c Release
```

`dotnet publish` выдаёт один файл `MACE.exe` (около 70 МБ) в `bin\Release\net8.0-windows\win-x64\publish`.

## Проверки

`tests\run_tests.py` гоняет собранный лаунчер по сценариям и сверяет результат на диске. Игру он не
запускает.

```
python launcher\tests\run_tests.py            все разделы
python launcher\tests\run_tests.py A B D      только названные
```

| Раздел | Что проверяется |
|---|---|
| A | повторный запуск ничего не качает |
| B | чужой мод и ресурспак уходят в `removed`, удалённый мод возвращается, оборванная загрузка докачивается, конфиг правил восстанавливается, `options.txt` и заметки игрока остаются |
| C | мод, убранный из сборки, удаляется без сообщения о чужом файле |
| D | файл занят другой программой: ошибка называет эту программу, после освобождения файл заменяется без повторного скачивания |
| E | первый источник отдаёт мусор вместо списка: берётся следующий |
| F | `--selftest`, команда запуска, ключ ника из пароля (пароль и закрытый ключ не попадают в журнал), отказ на короткий пароль |
| G | скачивание по HTTP с местного тестового сервера: докачка, обрыв связи, сервер без докачки, испорченный файл, уже скачанный файл, отсутствующий файл, зависшее соединение, недоступные адреса |
| H | окно: настройки (отказ на неверный параметр Java, «По умолчанию», сохранение и применение к команде запуска), проверка файлов, закрытие во время работы, сообщение об ошибке, короткий ник, вторая копия, пароль (отказ на пустой, «Показать», сохранение ключа, тот же ключ из командной строки, чужой ник, «Ввести заново») |

Раздел G идёт больше минуты: в нём дважды ждётся 30-секундный сброс зависшего соединения. Раздел H
на несколько секунд открывает окна лаунчера на экране. «ИГРАТЬ» с допустимым ником и паролем он нажимает
только при пустом источнике сборки: лаунчер сохраняет ключ и останавливается на ошибке, игра не стартует.
При сбое проверки печатается конец журнала лаунчера.

### Проверки с запуском игры

В `run_tests.py` их нет: они открывают игру, поэтому запускаются только вручную.

| Скрипт | Что делает |
|---|---|
| `tests\play_from_window.ps1 EXE ПАПКА ИСТОЧНИК НИК ФАЙЛ` | открывает окно лаунчера, вводит ник, нажимает «ИГРАТЬ» и записывает в файл, как менялась строка состояния, пока лаунчер не закроется |
| `tests\watch_game.ps1 -Root ПАПКА [-TitleLike ШАБЛОН] [-Shot ФАЙЛ.png] [-Close]` | находит игру по строке `PID` в `launcher.log`, ждёт конца загрузки (журнал игры молчит заданное число секунд), печатает заголовок окна и ошибки из журнала, снимает окно в PNG и по `-Close` закрывает игру |
| `tests\click_game.ps1 -Root ПАПКА -X N -Y N` | нажимает левой кнопкой мыши в точке окна игры (в пикселях от левого верхнего угла игрового поля). Перед нажатием проверяет, что в этой точке поверх остальных именно окно игры, иначе не нажимает |
| `python tests\auth_game_check.py` | проверяет пароль на ник входом в игру. Поднимает местный сервер Forge только с модом MACE Core (слушает `127.0.0.1:25566`, снаружи не виден) и раз за разом запускает через лаунчер игру тоже только с этим модом: первый вход с паролем, повторный вход, чужой пароль, вход без ключа, клиент прошлой версии мода, режимы `STRICT`, `SOFT` и `OFF`, сброс ника командой, новый клиент на сервере прошлой версии. Итог берётся из журнала сервера; для отказа по паролю окно игры снимается в `auth_refused.png`. Идёт около десяти минут |

Вход на сервер виден по заголовку окна: после подключения в нём появляется « - », поэтому
`-TitleLike "* - *"` ждёт именно его.

В PowerShell не запускайте лаунчер через `Start-Process -Wait`: этот ключ ждёт и дочерние процессы,
то есть саму игру. Нужен `$p = Start-Process ... -PassThru; $p.WaitForExit()`.

Что нужно для проверок:

- `Work\LauncherTest\source`: сборка в папке. Создаётся командой `python tools\upload_pack.py --stage ПАПКА`.
- `Work\LauncherTest\root`: установленная через лаунчер игра. Создаётся командой
  `MACE.exe --headless --sync --install --dir ПАПКА --source ПАПКА_СБОРКИ`.
- Для `auth_game_check.py` дополнительно: установленный сервер Forge в `Work\Server` (берутся его
  `libraries`) и собранные `macecore-1.8.0.jar` и `macecore-1.7.1.jar` в `Work\BattlefieldCore\build\libs`.
  Папки `LauncherTest\auth_server` и `LauncherTest\auth` скрипт создаёт сам.

## Список сборки

`manifest.json` создаёт `tools\make_manifest.py`, в релиз его выкладывает `tools\upload_pack.py`.
Описание формата и обоих скриптов: `tools\README.md`.
