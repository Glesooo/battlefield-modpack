# Battlefield — система обновлений (Packwiz)

Вместо заливки всей сборки на Google Диск при каждой правке: здесь лежит **манифест** (какие
файлы должны быть у игрока и с какими хэшами), сами моды хранятся как ассеты одного GitHub
Release, а игрок один раз кладёт апдейтер в свою папку `minecraft` и дальше просто запускает
его — скачивается только то, что реально изменилось.

Инструмент — [packwiz](https://packwiz.infra.link/), готовый и хорошо проверенный, писать
свой протокол синхронизации не понадобилось.

## Два апдейтера для игрока — какой раздавать

- **`gui/` — GUI-апдейтер (BattlefieldUpdaterGui), .NET/WPF, актуальная рекомендация.**
  Полноценное Windows-приложение с интерфейсом по референсу (`Zapros/Референс`): тёмная
  тема, сакура/пагода на фоне, шаги "Проверка → Загрузка → Установка → Готово", живой
  прогресс-бар (парсит вывод packwiz-installer построчно). Собирается честной компиляцией
  через `dotnet publish` — это НЕ PS2EXE-обёртка скрипта, а обычное .NET-приложение того же
  класса, что и тысячи легитимных программ, антивирусы его не подозревают по одному факту
  существования.
  **Сам exe (~156 МБ, самодостаточная сборка со встроенным рантаймом) НЕ лежит в git** —
  слишком большой и для репозитория, и для вложения в Discord (лимит 10 МБ без Nitro).
  Загружен как ассет GitHub Release `mod-files`, раздавать нужно **ссылкой**, не файлом:
  ```
  https://github.com/Glesooo/battlefield-modpack/releases/download/mod-files/BattlefieldUpdater.exe
  ```
  Ссылка на github.com вдобавок выглядит надёжнее, чем голый .exe-вложение в чате — так
  обычно и распространяют вредонос-боты в Discord, поэтому ссылка снимает вопрос доверия
  ещё до всякого антивируса.
- **`update.bat` — текстовый батник, запасной вариант.** Тот же результат (диалог выбора
  папки, докачка разницы), но без всякой компиляции вообще — на случай, если у кого-то
  не заведётся .NET-рантайм или GUI-версия сама попадёт под какую-то эвристику. Можно
  положить рядом как альтернативу, но выглядит менее презентабельно для нетехнических
  людей — отсюда и переход на GUI.

## Файлы в этой папке

- `pack.toml` / `index.toml` / `mods/` / `tacz/` / `config/` — манифест packwiz (см. ниже).
- `publish.ps1` — запускаешь **ты** при каждом обновлении сборки контента (моды/ганпаки/конфиги).
- `update.bat` — запасной апдейтер для игрока (см. выше).
- `gui/BattlefieldUpdaterGui/` — исходники GUI-апдейтера. Пересборка:
  ```powershell
  cd gui\BattlefieldUpdaterGui
  dotnet publish -c Release
  # результат: bin\Release\net8.0-windows\win-x64\publish\BattlefieldUpdater.exe
  ```
  После пересборки — залить в тот же Release (не в git!):
  ```powershell
  gh release upload mod-files ".\bin\Release\net8.0-windows\win-x64\publish\BattlefieldUpdater.exe" --repo Glesooo/battlefield-modpack --clobber
  ```
  Ссылка для игроков не меняется — тот же URL, `--clobber` просто подменяет файл под ним.
  Фон (`Assets/background.png`) — референсный арт пользователя, при желании сменить —
  просто заменить файл и пересобрать, размеры/пропорции подбираются автоматически
  (`Stretch=UniformToFill`).

## Как это устроено

- `pack.toml` / `index.toml` — манифест packwiz, реген через `packwiz refresh`.
- `mods/*.toml` — по одному файлу на мод (~90 штук, ~0.48 ГБ). Сам jar НЕ лежит в git — только
  имя, хэш и прямая ссылка на GitHub Release с ассетами (тег `mod-files`).
- `tacz/` — тут ДВЕ разные вещи в одной папке, это осознанно (у ганпаков-zip и мелких файлов
  рядом с ними общий целевой путь на компьютере игрока — `<инстанс>/tacz/`):
  - **`tacz/*.toml`** — большие zip-ганпаки (~0.5 ГБ) — тем же способом, что моды: сам zip
    только на GitHub Release, здесь — указатель.
  - **Остальное в `tacz/`** (несколько мелких распакованных подпапок вроде `daffas/`,
    `endlessammo/` — похоже, их сами создают некоторые ганпак-моды при первом запуске — плюс
    пара служебных файлов) — обычные файлы прямо в git, как конфиги ниже.
  - `publish.ps1` не путает эти два вида между собой (раздельная логика очистки/копирования),
    но если руками полезешь в эту папку — не трогай `.toml`, это чужая зона.
- `config/` — копия **только** общей клиентской `PrismLauncher/instances/M.A.C.E/minecraft/config/`
  (~1.4 МБ, обычные файлы прямо в git). Раз решили затирать конфиги под твою версию — так оно и
  работает: у packwiz это поведение по умолчанию для любого отслеживаемого файла, никакого
  спецфлага не нужно.
- **Специально НЕ трогается:** `saves/` целиком (это мир игрока, не часть сборки) и, отдельно,
  `saves/<мир>/serverconfig/` — в Forge 1.20.1 серверные конфиги (`FactionConfig`,
  `DeathmatchConfig` и т.п.) хранятся **внутри сохранения мира**, а не в общей папке. Это данные
  конкретного игрока/мира — апдейтер их не видит и не трогает.

Суммарно на момент настройки — mods (~0.48 ГБ) + tacz (~0.5 ГБ) + config (~1.4 МБ) ≈ 1 ГБ.
Если реальный вес сборки у тебя больше (упоминал ~1.7 ГБ) — вероятно, за счёт `saves/` (мир
весит немало) или ресурспаков/шейдеров; если появятся `resourcepacks/`/`shaderpacks/` с
содержимым — скажи, добавлю их в `publish.ps1` той же схемой (бинарники крупнее нескольких МБ
— через Release, мелочь — как конфиги).
