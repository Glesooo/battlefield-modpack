# Battlefield — система обновлений (Packwiz)

Вместо заливки всей сборки на Google Диск при каждой правке: здесь лежит **манифест** (какие
файлы должны быть у игрока и с какими хэшами), сами моды хранятся как ассеты одного GitHub
Release, а игрок один раз кладёт `BattlefieldUpdater.exe` в свою папку `minecraft` и дальше
просто запускает его двойным кликом — скачивается только то, что реально изменилось.

Инструмент — [packwiz](https://packwiz.infra.link/), готовый и хорошо проверенный, писать
свой протокол синхронизации не понадобилось.

## Файлы в этой папке

- `pack.toml` / `index.toml` / `mods/` / `tacz/` / `config/` — манифест packwiz (см. ниже).
- `publish.ps1` — запускаешь **ты** при каждом обновлении сборки.
- `update.ps1` — исходник апдейтера для игрока (PowerShell).
- `BattlefieldUpdater.exe` — то же самое, скомпилированное в exe через
  [PS2EXE](https://github.com/MScholtes/PS2EXE) (двойной клик вместо "запусти .ps1 через
  PowerShell"). Именно этот файл раздаёшь игрокам.

## Как это устроено

- `pack.toml` / `index.toml` — манифест packwiz, реген через `packwiz refresh`.
- `mods/*.toml` — по одному файлу на мод (~90 штук, ~0.48 ГБ). Сам jar НЕ лежит в git — только
  имя, хэш и прямая ссылка на GitHub Release с ассетами (тег `mod-files`).
- `tacz/` — тут ДВЕ разные вещи в одной папке, это осознанно (у ганпаков-zip и мелких файлов
  рядом с ними общий целевой путь на компьютере игрока — `<инстанс>/tacz/`):
  - **`tacz/*.toml`** — большие zip-ганпаки (~0.5 ГБ) — тем же способом, что моды: сам zip
    только на GitHub Release, здесь — указатель.
  - **Остальное в `tacz/`** (несколько мелких распакованных подпапок вроде `daffas/`,
    `endlessammo/` — похоже, их сами создают некоторые ганпак-моды при первом запуске — плюс
    пара служебных файлов) — обычные файлы прямо в git, как конфиги ниже.
  - `publish.ps1` не путает эти два вида между собой (раздельная логика очистки/копирования),
    но если руками полезешь в эту папку — не трогай `.toml`, это чужая зона.
- `config/` — копия **только** общей клиентской `PrismLauncher/instances/M.A.C.E/minecraft/config/`
  (~1.4 МБ, обычные файлы прямо в git). Раз решили затирать конфиги под твою версию — так оно и
  работает: у packwiz это поведение по умолчанию для любого отслеживаемого файла, никакого
  спецфлага не нужно.
- **Специально НЕ трогается:** `saves/` целиком (это мир игрока, не часть сборки) и, отдельно,
  `saves/<мир>/serverconfig/` — в Forge 1.20.1 серверные конфиги (`FactionConfig`,
  `DeathmatchConfig` и т.п.) хранятся **внутри сохранения мира**, а не в общей папке. Это данные
  конкретного игрока/мира — апдейтер их не видит и не трогает.

Суммарно на момент настройки — mods (~0.48 ГБ) + tacz (~0.5 ГБ) + config (~1.4 МБ) ≈ 1 ГБ.
Если реальный вес сборки у тебя больше (упоминал ~1.7 ГБ) — вероятно, за счёт `saves/` (мир
весит немало) или ресурспаков/шейдеров; если появятся `resourcepacks/`/`shaderpacks/` с
содержимым — скажи, добавлю их в `publish.ps1` той же схемой (бинарники крупнее нескольких МБ
— через Release, мелочь — как конфиги).

## Разовая настройка (сделать один раз, по порядку)

### Шаг 1 — авторизовать GitHub CLI

Под своим аккаунтом — это должен сделать ты сам, я не могу войти за тебя:
```powershell
gh auth login
```
Отвечай на вопросы так: `GitHub.com` → `HTTPS` → `Login with a web browser` → нажать Enter,
скопировать показанный код, он откроет браузер сам (или открыть ссылку вручную) → вставить код
→ авторизовать. После этого в консоли появится "Logged in as ...".

Проверить, что получилось:
```powershell
gh auth status
```

### Шаг 2 — создать репозиторий на GitHub

Публичный (решили без регистрации у игроков — `BattlefieldUpdater.exe` рассчитан именно на
это, открытая ссылка без токенов):
```powershell
cd "C:\Users\Gleso\Desktop\Project\Minecraft\Work\ModpackDist"
gh repo create battlefield-modpack --public --source=. --remote=origin --push
```
`--push` сразу отправит уже сделанный начальный коммит. Если команда прошла без ошибок —
открой `https://github.com/<твой-логин>/battlefield-modpack` в браузере и убедись, что файлы
там появились.

Имей в виду: часть сторонних модов лицензирована как All Rights Reserved — публичный
репозиторий не более "публичен", чем сейчас ссылка на Google Диск, которую можно переслать
кому угодно, но технически файлы будет видно всем, у кого есть прямая ссылка на репозиторий
(не индексируется поисковиками сам по себе, но и не защищено логином). Если станет
некомфортно — перевести в приватный можно в любой момент
(`gh repo edit --visibility private`), тогда игрокам придётся заводить GitHub-аккаунт.

### Шаг 3 — вписать адрес репозитория в апдейтер и пересобрать exe

Открой `update.ps1`, найди строку:
```powershell
$PackUrl = "https://raw.githubusercontent.com/OWNER/REPO/main/pack.toml"
```
замени `OWNER/REPO` на `<твой-логин>/battlefield-modpack`. Сохрани.

Пересобери `BattlefieldUpdater.exe` (модуль ps2exe уже скачан в
`%TEMP%\claude\PS2EXE\Module\ps2exe.psd1` в этой сессии — если его там больше нет, склонируй
заново: `git clone https://github.com/MScholtes/PS2EXE.git` куда угодно и подставь свой путь
ниже):
```powershell
Import-Module "$env:TEMP\claude\PS2EXE\Module\ps2exe.psd1" -Force
Invoke-ps2exe -inputFile ".\update.ps1" -outputFile ".\BattlefieldUpdater.exe" `
    -title "Battlefield Updater" -product "Battlefield Modpack" -company "Gleso" `
    -version "1.0.0.0" -x64 -noConsole:$false
```

### Шаг 4 — первая публикация

Загрузит все ~87 модов, ганпаки и конфиги на GitHub Release — минут 5-10 в зависимости от
скорости интернета:
```powershell
.\publish.ps1 -Repo "<твой-логин>/battlefield-modpack"
```
Это первый прогон скрипта на реальном объёме файлов (87 разных сторонних jar с кириллицей,
скобками, апострофами в именах) — после него стоит один раз глянуть `git log` / зайти на
GitHub и проверить, что Release действительно наполнился файлами, а не только их часть.

### Шаг 5 — закоммитить обновлённый exe и update.ps1

```powershell
git add update.ps1 BattlefieldUpdater.exe
git commit -m "Point updater at the real repo"
git push
```
(Можно и одновременно с шагом 4 — `publish.ps1` тоже коммитит и пушит, но по своим файлам;
эти два коммить отдельно, раз меняешь их вручную не через скрипт.)

## Как публиковать обновления дальше (после разовой настройки)

Просто:
```powershell
cd "C:\Users\Gleso\Desktop\Project\Minecraft\Work\ModpackDist"
.\publish.ps1 -Repo "<твой-логин>/battlefield-modpack"
```
Скрипт сам найдёт, какие jar'ы в `mods/`, zip-ганпаки в `tacz/` и файлы в `config/`
добавились/изменились/пропали, перезальёт только их, обновит манифест и запушит. Если менял
только один мод (например, пересобрал `HudElements`) — перезальётся только он, остальное не
тронется. `update.ps1`/`BattlefieldUpdater.exe` трогать заново не нужно — адрес репозитория
в них уже прописан один раз навсегда.

## Что нужно сделать игроку (один раз)

1. Скачать `BattlefieldUpdater.exe` (ссылку на GitHub-репозиторий или сам файл — как удобнее
   передать: Discord, ссылка на raw-файл из репозитория и т.п.).
2. Положить его прямо в `PrismLauncher\instances\<Имя инстанса>\minecraft\` (рядом с папками
   `mods`, `config`, `saves`).
3. Запускать двойным кликом каждый раз, когда сказано, что вышло обновление. У игрока должна
   быть установлена Java (она и так нужна для Minecraft) — если её не найдёт, exe сам скажет
   об этом текстом, а не просто закроется.

Первый запуск скачает всю сборку (раз ничего ещё не установлено) — так же долго, как раньше
через Диск. Дальше — только разницу.

## Если что-то пошло не так

- **Окно с ошибкой "Failed to download pack.toml... 404"** — апдейтер стучится по адресу,
  которого не существует. Либо ещё не сделан Шаг 3 (в exe вписан плейсхолдер), либо опечатка в
  адресе репозитория, либо `publish.ps1` ещё ни разу не запускался (нет `pack.toml` в ветке
  `main` репозитория).
- **"Java not found on PATH"** — у игрока нет Java в системном PATH (PrismLauncher иногда
  ставит свою Java отдельно, не в PATH). Попросить установить Java с adoptium.net/java.com.
- **`gh release upload` падает в `publish.ps1`** — скорее всего `gh auth login` слетел или не
  сделан. Проверить `gh auth status`.
